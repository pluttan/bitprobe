# Bonsai не квантизация: я сравнил однобитную модель с Qwen и нашёл следы обучения

Компания PrismML выпустила модели Bonsai. Это языковые модели, у которых вес в блоках занимает один бит. Авторы открыли формат, ядра для llama.cpp и MLX, простой квантизатор. Закрытым остался один шаг: преобразование, после которого знаковая квантизация перестаёт разрушать модель. В описании этот шаг назван «proprietary Caltech IP».

Я хотел понять, что это за шаг. Для этого я написал инструмент bitprobe. Он сравнивает однобитную модель с полноточной моделью, из которой её получили. Ответ оказался неожиданным: шага преобразования нет. Bonsai обучили, а не пересчитали.

Ниже я описываю:

- как инструмент читает модели по сети;
- какие числа показал первый замер;
- почему мой решатель выиграл по своей метрике и уничтожил модель;
- какие признаки отличают обученные веса от пересчитанных;
- что получилось, когда я сам обучил однобитную модель.

## Инструмент: модель на 27B с ноутбука

Модели для сравнения весят десятки гигабайт. Мне нужны были несколько матриц из каждой. Поэтому bitprobe не скачивает модель, а читает байты по HTTP range.

Формат safetensors для этого удобен. Файл начинается с восьми байт длины заголовка. Затем идёт заголовок в JSON. В нём указаны имя, тип, форма и смещение каждого тензора. Заголовок занимает несколько килобайт при любом размере модели.

```python
def header(repo: str) -> dict[str, dict]:
    index = {}
    for shard in _shards(repo):
        url = f"{HF}/{repo}/resolve/main/{shard}"
        size = int.from_bytes(_get(url, 0, 8), "little")
        meta = json.loads(_get(url, 8, size))
        meta.pop("__metadata__", None)
        for name, entry in meta.items():
            index[name] = {**entry, "url": url, "base": 8 + size}
    return index
```

Матрицы хранятся построчно. Поэтому первые N строк матрицы лежат одним непрерывным диапазоном байт. Для статистики хватает 256 строк, и по сети идут сотни килобайт.

CDN обрезает чтение длиной в сотни мегабайт. Поэтому большие диапазоны инструмент делит на куски по 48 МБ. Под нагрузкой отдельные запросы падают, и повтор с паузой их восстанавливает.

### Ошибка без сообщения об ошибке

Базовые модели лежат в BF16, однобитные модели в F16. Оба формата занимают 2 байта. Если прочитать BF16 как F16, программа не упадёт. Знаки останутся верными, потому что старший бит у форматов общий. Величины будут неверными, но правдоподобными. Метрики при этом выглядят осмысленно, и ошибку долго не замечают.

BF16 совпадает со старшей половиной float32. Поэтому декодирование занимает одну строку:

```python
if dtype == "BF16":
    half = np.frombuffer(raw, dtype=np.uint16).astype(np.uint32)
    return (half << 16).view(np.float32)
```

### Сравнение с округлением, а не с оригиналом

Косинус между однобитной матрицей и оригиналом сам по себе ничего не говорит. Неясно, хорошее это число или плохое. Поэтому bitprobe считает рядом округление. Дальше в статье этим словом я называю знак веса и средний модуль группы из 128 весов в качестве масштаба.

```python
def naive_binary(w, group=128):
    g = w.reshape(w.shape[0], -1, group)
    scale = np.abs(g).mean(axis=2, keepdims=True)
    return (np.sign(g) * scale).reshape(w.shape)
```

Любой метод должен обыграть именно это округление. Иначе в методе нет смысла.

Команды инструмента:

- `info` показывает размер группы, тип и долю нулей;
- `compare` сравнивает один тензор с базой и с округлением;
- `flips` строит долю перевёрнутых знаков по децилям величины веса;
- `profile` обходит все слои и показывает отклонение на каждой глубине.

Размер группы инструмент находит без метаданных. В однобитной строке одна величина повторяется на всю группу. Расстояние между сменами величины и даёт размер группы.

## Первый замер: Bonsai дальше от весов, чем округление

Я сравнил `prism-ml/Bonsai-1.7B-unpacked` с `Qwen/Qwen3-1.7B`. Вот одна матрица первого блока:

```
model.layers.0.mlp.gate_proj.weight  [256, 2048]
  cos(model, base)        +0.4886
  cos(naive binary, base) +0.7909
  cos(naive ternary, base)+0.8926
  sign agreement          71.0%
  relative error          1.354
  naive relative error    0.612
  scale vs mean|w|        1.990
  zero fraction           0.0%
```

Косинус Bonsai с оригиналом равен 0,49. У округления он равен 0,79. По всем слоям картина одна: у Bonsai 0,41–0,58, у округления 0,79.

Из этого следуют три факта:

- Bonsai не приближает веса Qwen. Округление приближает их лучше.
- Знак не совпадает у 29 % весов этой матрицы. Округление не меняет ни одного знака.
- Масштаб группы примерно вдвое больше среднего модуля. Формула такого числа не даёт.

Получается, что метод ищет другую конфигурацию знаков. Эта конфигурация далека от весов, но сеть с ней ведёт себя так же.

## Гипотеза: послойный решатель

Первая гипотеза была такой: Bonsai решает задачу для каждого слоя отдельно. Цель решателя: выход слоя, а не его веса. Так работают GPTQ и его предок Optimal Brain Surgeon. Один из авторов Optimal Brain Surgeon, Babak Hassibi, руководит PrismML. Гипотеза выглядела правдоподобной.

Я написал решатель. Он перебирает знаки покоординатным спуском и минимизирует ошибку выхода слоя на реальных активациях. Ошибку оценивает гессиан этих активаций.

На `layers.0.self_attn.q_proj` решатель дал ошибку выхода 0,30 против 0,55 у округления. Косинус с весами упал до 0,60. Подпись Bonsai повторилась: веса ушли дальше, а выход стал точнее.

Затем я собрал из таких слоёв всю модель и измерил перплексию:

| модель | перплексия |
|---|---|
| Qwen3-1.7B, fp16 | 12,32 |
| Bonsai, 1 бит | 16,53 |
| мой решатель | 923 707 |

### Решатель решал не ту задачу

Решатель выигрывает по своей метрике и разрушает модель. Причина видна, если оценить слой на тексте вне калибровки:

| слой | ошибка на калибровке | ошибка вне калибровки | число обусловленности гессиана |
|---|---|---|---|
| q_proj | 0,1207 | 0,3142 | 4,7e12 |
| v_proj | 0,2429 | 0,5843 | 4,7e12 |
| up_proj | 0,2653 | 0,5726 | 1,6e13 |
| down_proj | 0,2144 | 0,6957 | 4,5e07 |

Восемь тысяч токенов калибровки не определяют гессиан размерности 2048 или 6144. У такого гессиана есть почти нулевые направления. Решатель уводит веса в эти направления. Там цель на калибровке ничего не стоит, а на реальном тексте ошибка большая.

Регуляризация на 1 % от среднего собственного значения не помогает. Главную часть следа дают несколько признаков с выбросами.

## Доказательство: Bonsai обучали

Тогда я перестал искать решатель и стал смотреть на сами веса.

**Все 196 матриц однобитные.** На группу из 128 весов приходится одна величина. Нулей нет. Таблица эмбеддингов тоже однобитная.

**Эмбеддинги получены округлением Qwen.** Знаки совпадают в 99,93 % случаев. Масштаб точно равен `mean|w|`. Значит, Bonsai построена на Qwen3-1.7B. Всё, что сдвинулось в блоках, сдвинулось намеренно.

**Перевороты знаков зависят от величины веса.** В блоках не совпадает от 21 до 36 % знаков. Среди самых мелких весов перевёрнуто 48 %, среди самых крупных 5,6 %.

Такой профиль даёт градиентный спуск от знаковой инициализации. Мелкий вес часто переходит через ноль. Крупный вес почти не переходит. Решатель такого профиля не даёт: он переворачивал крупные веса почти так же часто, как мелкие.

**Внутренние состояния не совпадают, выход совпадает.** На блоке 2 косинус скрытых состояний Bonsai и Qwen равен 0,10. При этом первый по вероятности токен совпадает в 70 % случаев. Среднее расхождение KL равно 0,55. Значит, авторы подгоняли не внутренности сети, а только её предсказания.

**Конфигурация отличается от Qwen.** В Bonsai стоит YaRN с 8192 до 32768 токенов. Словарь урезан до 151 669 токенов. У Qwen3-1.7B нет ни того, ни другого.

Вывод: матрицы Bonsai не приближают матрицы Qwen. Это другая сеть, которая вычисляет ту же функцию. Метод после обучения такую сеть не воспроизведёт по построению. Поэтому и закрытый шаг оказался рецептом обучения, а не решателем.

## Обучение знаков вместо решения

Дальше я решил обучить знаки сам. Параметризация та же: знак веса и масштаб группы. Градиент проходит через знак прямым оценщиком (STE). Я обучал по одному блоку. Вход блока брался из уже бинаризованной части сети, цель из чистого выхода учителя.

Блок 0, ошибка блока и перплексия всей модели:

| вариант | ошибка блока | перплексия |
|---|---|---|
| округление | 0,8609 | 484 621 |
| решатель | 0,7159 | 5 525 |
| обучение, 46 секунд | 0,5570 | 345 |

Профиль переворотов совпал с Bonsai по форме. Среди мелких весов перевёрнуто 44 %, среди крупных 0,2 %.

Затем я сравнил варианты на блоке 0. Каждый вариант начинал с исходных весов.

| вариант | ошибка блока |
|---|---|
| округление | 0,8690 |
| знаки, 40 тыс. токенов | 0,5042 |
| знаки, 40 млн токенов | 0,3883 |
| знаки и масштабы, 40 млн токенов | 0,3652 |
| только масштабы, 40 млн токенов | 0,5403 |

Объём данных даёт больше всего. Обучаемый масштаб тоже помогает, и это согласуется с масштабом Bonsai.

После обучения всех 28 блоков результат такой:

| модель | перплексия |
|---|---|
| Qwen3-1.7B, fp16 | 12,32 |
| Bonsai, 1 бит | 16,53 |
| мой решатель | 923 707 |
| обученные знаки | 7 044 |
| знаки, масштабы и корпус | 1 680 |

### Почему обучение по блокам упирается в предел

Каждый блок исправляет только ошибку, которую получил от блоков до него. Он не знает, что с его выходом сделают блоки после него. Поэтому ошибка накапливается с глубиной: 0,20 на блоке 3 и 0,52 на блоке 23. Лучшая подгонка каждого блока этого не меняет.

Убирает накопление только потеря на логитах. Тогда в графе обучения находится вся сеть сразу. Это дистилляция по выходу учителя. Её стоимость для модели 1,7B я оценил так:

| токенов | FLOPs | 12×A100 при загрузке 40 % |
|---|---|---|
| 10 млрд | 1,4e20 | около 25 часов |
| 30 млрд | 4,1e20 | около 3 суток |

На ноутбуке такое не запустить. Поэтому я вынес обучение в отдельный проект.

## bindistill: однобитная модель за 15 часов на одной карте

Проект bindistill обучает однобитную копию модели по выходу полноточной модели. Учитель работает рядом на каждом шаге. Студент отличается от него только матрицами блоков. В умножение попадают знак веса и обучаемый масштаб группы.

Шаг обучения:

1. Окно текста идёт в учителя. Учитель выдаёт распределение следующего токена.
2. То же окно идёт в студента.
3. Потеря складывается из расхождения распределений и обычной потери на следующем токене.
4. Градиент доходит до хранимого полноточного веса. Знак берётся от этого веса, а сам вес продолжает двигаться.

Первый прогон: учитель Qwen3-0.6B, 300 млн токенов FineWeb-Edu, одна видеокарта, около 15 часов.

| модель | перплексия | совпадение первого токена |
|---|---|---|
| учитель | 25,02 | – |
| однобитный студент | 27,85 | 0,698 |
| округление тех же 196 матриц | 6 877 887 | – |

Перплексия студента на 11 % выше, чем у учителя. Кривая обучения на плато не вышла: 81,9, 42,7, 34,6, 30,2, 27,85.

Профиль переворотов у студента такой же, как у Bonsai. По децилям величины веса от мелких к крупным: 45,8, 37,8, 30,1, 22,7, 15,3, 8,5, 3,3, 0,8, 0,2 и 0,02 %. Косинус с исходными весами равен 0,67, у округления 0,79. Модель снова ушла от весов дальше округления и при этом работает.

Второй прогон шёл на двух A100 и смеси доменов olmo-mix-1124, 700 млн токенов:

| модель | перплексия | совпадение первого токена | учитель в пятёрке студента | совпадение, когда учитель уверен |
|---|---|---|---|---|
| учитель | 11,72 | 1,000 | 1,000 | 1,000 |
| округление | 3 645 563 | 0,000 | 0,001 | 0,000 |
| студент | 15,73 | 0,722 | 0,935 | 0,964 |

Учитель уверен на 30 % токенов, то есть даёт своему выбору вероятность от 0,9. На этих токенах студент повторяет выбор в 96,4 % случаев. Расхождения лежат там, где сам учитель колеблется.

### Что даёт один бит на практике

Внутри матрицы блока вес занимает 1,125 бита: бит знака и 16-битный масштаб на 128 весов. Но в модели есть не только блоки. У Qwen3-0.6B словарь из 151 936 токенов занимает 155,6 млн параметров из 596 млн. Эта таблица остаётся в 16 битах.

| представление | объём | сжатие |
|---|---|---|
| 16 бит на вес | 1137 МБ | – |
| 1 бит в блоках, 16 бит вне блоков | 356 МБ | ×3,19 |
| только матрицы блоков | 840 → 59 МБ | ×14,22 |

Скорость генерации и память во время работы не изменились: 37,2 токена в секунду у обеих моделей. В bindistill нет ядра для упакованных битов. При запуске однобитные матрицы разворачиваются в bfloat16. Выигрыш пока есть только при хранении и передаче модели.

## Как отличить обученную модель от пересчитанной

Из этой работы получился признак обучения. Для него нужны только два набора весов: исходный и низкоразрядный. Данные и запуск модели не нужны.

Постройте долю перевёрнутых знаков по децилям величины исходного веса:

```bash
python main.py flips prism-ml/Bonsai-1.7B-unpacked Qwen/Qwen3-1.7B \
    model.layers.0.mlp.gate_proj.weight
```

Возможны три результата:

- Знаки не перевёрнуты. Это округление.
- Перевороты есть, но почти не зависят от величины веса. Это похоже на послойный решатель.
- Мелкие веса перевёрнуты часто, крупные почти никогда. Это градиентное обучение.

Тот же признак помогает при своём обучении. Если перевороты не зависят от величины веса, обучение не идёт. Так можно понять это раньше, чем по перплексии.

## Чего эта работа не показала

- Все замеры обучения сделаны на модели 0,6B. На моделях в десятки миллиардов параметров выводы не проверены.
- Бюджет в 300 млн токенов выбран по доступному времени. Часть разрыва с учителем может объясняться недообучением.
- Вне корпуса для обучения разрыв растёт. На художественном тексте перплексия студента в 1,60 раза выше, чем у учителя. На отложенной части корпуса разница 1,11 раза.
- Все корпуса и тексты для замеров английские.
- Замеров на прикладных наборах задач нет.
- Признак по профилю переворотов проверен на двух случаях. Для оценки его надёжности нужен набор моделей с известной историей.
